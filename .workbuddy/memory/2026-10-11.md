## 2026-10-11 后续：明确「推荐」与「直接」接单差异

用户反馈「直接接单和推荐接单好像加成啊」，意思是两者看起来收益一样，好像都有小费。

核查代码逻辑：
- `accept(id, 'tell')` → 出餐时 `tip = discount * rates.tip`
- `accept(id, 'skip')` → 出餐时 `tip = 0`，只有餐费

验证无误。但 UI 上两个按钮都叫「接单」，确实容易让人误以为结果一样。

已调整 `src/index.html`：
- 待接单按钮：「推荐 +小费」/「直接 无小费」
- 已接单提示：「✓ 推荐 +小费」/「✓ 直接 无小费」
- 优惠标签：「本单可省 ¥X · 推荐后出餐才有小费」
- 接单提示语：明确说「出餐后仅收餐费，无小费」或「可获优惠金额 ×N 的小费」
- 玩法说明：加粗「推荐优惠才赚小费」，并说明直接接单仅收餐费

已重新跑测试（14 passing）并重新构建。

## 2026-10-11 后续：顾客词条平衡调整

用户反馈「所有词条都是会发现漏掉优惠的」，即感觉所有顾客都会抓漏推优惠。

检查后发现：6 个词条里有 4 个 couponAttention ≥ 0.55，平均 catch 率高达 56%，确实让玩家觉得跳过优惠几乎必被抓。

已调整 `src/index.html` 中 `TRAITS` 的 couponAttention 与 hint：
- 省钱小能手：0.96 → 0.85
- 佛系干饭人：0.08 → 0.05
- 打工赶时间：0.35 → 0.20
- 探店博主：0.78 → 0.60
- 认真核对客：0.65 → 0.45
- 麦麦熟客：0.55 → 0.35

平均 catch 率从 56% 降至约 41%，且每个 hint 明确提示该顾客对优惠的敏感程度。

已重新运行测试（14 passing）并重新构建 `maimai-restaurant.html`。
